# Bitácora — 2026-07-17 — Inicio Tanda 0

## Trabajo realizado

- se analizó el prompt maestro de producto;
- se revisó un proyecto previo únicamente como referencia metodológica, sin copiar contenido;
- se verificó que `CICUC-2026` no tenía repositorios;
- se crearon tres repositorios privados exclusivos de CICUC;
- se creó el Project 1 `Gestión de estudios clínicos`;
- se definieron aislamiento, visión, alcance, arquitectura, seguridad, UX, calidad y ADRs iniciales.

## Decisiones

- frontend React/TypeScript moderno;
- backend FastAPI/PostgreSQL como monolito modular;
- API REST `/api/v1`;
- navegación horizontal superior;
- identidad visual propia de CICUC;
- primera versión sin IA y con decisión clínica humana.

## Pendientes

- validar matriz detallada de permisos con CICUC;
- validar retención y fundamento legal del tratamiento de datos;
- recibir insumos de identidad de marca;
- descomponer el backlog en HUs verificables;
- iniciar scaffolding técnico solo después de consolidar la fundación documental.

## Continuación — primer incremento técnico

- HU-001 implementó FastAPI, salud versionada, PostgreSQL configurable, Alembic, estructura modular, Docker y CI;
- HU-002 implementó React/TypeScript/Vite, layout responsivo con barra horizontal, identidad neutral CICUC y CI;
- backend verificado con Ruff, MyPy, 2 tests, migración real arriba/abajo y build Docker en Actions;
- frontend verificado con ESLint, TypeScript, 2 tests de componentes, build, 4 pruebas Playwright y revisión visual;
- no se agregaron autenticación, datos clínicos ni decisiones automáticas.

## Continuación — HU-003

- se implementaron usuarios administrados, Argon2, tokens opacos, expiración, revocación y bloqueo temporal;
- desactivar una cuenta revoca sus sesiones y el cambio de contraseña revoca las demás;
- se incorporó auditoría inicial sin registrar credenciales ni tokens;
- se agregó login responsivo y protección de rutas conservando la navegación horizontal;
- se verificaron 11 tests backend, 5 tests frontend, 6 Playwright simulados y 1 E2E contra API/PostgreSQL reales;
- las migraciones se verificaron arriba, abajo y arriba sobre PostgreSQL 16;
- recuperación automática, SSO, MFA y permisos clínicos permanecen fuera de este incremento.
